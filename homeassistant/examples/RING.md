# Optional Ring delivery hints (backend 1.6.2)

[Deutsch](RING.de.md)

Install Worker 2.2.0 and the current Jarvis integration; select your authorized Ring recording cameras in the integration settings. The example package is **not installed automatically**. Inspect it before enabling; replace `notify.example_speaker` with your own notification target(s), and `https://YOUR-AUDIO-HOST.example` with your trusted reachable audio server. It assumes an existing `rest_command.piper_generate` returning status/content/path as used by Jarvis. Do not copy credentials into the repository. Enable HA packages using the documented HA configuration, or adapt the individual script/helpers/automations in the UI; do not duplicate existing entity IDs.

Call `script.ring_ki_bildanalyse_seriell` from your own recording-ready automations with `camera_source` (door/outside), unique `ring_request_id`, `event_time` (recording timestamp ISO), and `recording_entity` (your Ring recording timestamp sensor). Ensure these refer to the same recording; the example rejects a timestamp mismatch. The script emits `jarvis_infobox_update` with summary, evidence, assessment, profile, timing, and recording time. Only explicit authorized recordings are analyzed, with no identity recognition. The journal stores descriptions in recorder attributes; configure retention and access appropriately. The legacy helper retains a bounded summary. Notification dispatch is not playback confirmation. A 45-second heuristic suppresses one probable cross-camera duplicate; it can merge distinct nearby deliveries. Separate package-placement notices remain possible; quiet hours are 22:00–06:00. Disable or adjust the automation to your needs. No private dashboard modules included. Test with synthetic events first, then authorized local recordings. The example has not been exercised on a fresh HA installation.
